# 前期调研：公众号自动化监控 / 搜索 / 查询的手段

> 调研时间：2026-10-02。这是 wxmp 选型的依据，结论会随微信风控变化而过时。

## 结论先行

**微信从未开放"全网公众号文章检索/监控"的公开 API。** 所有方案本质上都在绕这个限制，
而且微信在**持续收紧**（WeWe RSS 原仓库已于 2026-05 归档；2026-07-30/31 起，
后台跨公众号文章列表接口 `appmsgpublish` 集体返回 `ret=200013`）。

所以 wxmp 的基本假设是：**任何上游都可能在半年内失效**，要把原始响应永久留档，
并让上游可替换。

---

## 一、官方通道（合规但几乎没用）

| 通道 | 能力 | 对监控的价值 |
|---|---|---|
| 公众平台开发者 API | 只能查**自己主体下**的号 | 零。拿不到别人的号 |
| 微信搜一搜（小程序侧） | `wxaapi_submitpages` 是"提交收录"，不是查询 | 零 |

## 二、技术路线

| 路线 | 能拿到 | 稳定度 | 备注 |
|---|---|---|---|
| 公众号后台抓包回采 | 全量历史列表 + 阅读/在看 | 中→差 | 编辑器"插入超链接"调的 `/cgi-bin/appmsg?action=list_ex`；2026-07 起跨号列表报 200013 |
| 搜狗微信搜索 | 关键词检索 | 差 | 唯一公开索引公众号的搜索引擎，验证码频繁 |
| 微信读书接口转 RSS | 正文 + 更新 | 中 | WeWe RSS 已归档；Wechat2RSS 仍在维护 |
| 直接爬 mp.weixin.qq.com | 正文 | 中 | `wappoc_appmsgcaptcha` 验证码；阅读数只在登录态渲染 |
| 第三方数据 API | 视厂商 | 付费即稳定 | wxmp 选了这条 |

### 开源工具

- [we-mp-rss](https://github.com/rachelos/we-mp-rss)：Docker 一键起，扫码授权后订阅，输出 RSS/MD/PDF，带 Webhook/API/MCP
- [wechatDownload](https://github.com/qiye45/wechatDownload)：批量下载历史文章，支持 MCP/Skill
- [Wechat2RSS](https://wechat2rss.xlab.app/)：公开服务免费收录 300+ 号；**私有部署 15 元/月、150 元/年**（买授权自部署），平均时延约 6 小时
- [WeWe RSS](https://github.com/cooderl/wewe-rss)：基于微信读书，**已归档只读**

## 四、时效性：两种延迟别混淆

- **采集延迟**：发布 → 进入第三方库。决定能不能用 API 监控。
- **收录延迟**：发布 → 搜一搜/搜狗能搜到。官方口径新内容**最长约 48 小时**才能被搜到。

监控"某号发了新文"要的是前者。

## 五、TikHub 实测（2026-10-02，样本：「仓都加满」）

原始响应见 [`../dev/api-samples/`](../dev/api-samples/)。

| 接口 | 耗时 | 结果 |
|---|---|---|
| `wechat_search/v2/fetch_search`（account） | 28.4s | 14 条，含李鬼与同名视频号 |
| `wechat_mp/v2/fetch_account_profile` | 2.6s | 原创 738 篇、深圳 |
| `wechat_mp/v2/fetch_account_articles` | **2.3s** | 每次约 10 条，`page_size` 被忽略，翻页只能用 `next_offset` |
| `wechat_mp/v2/fetch_article_detail_h5` | 8.1s | `content_text` 纯文本 1129 字、`content_noencode` HTML 14784 字 |
| `wechat_mp/v2/fetch_article_stats_h5` | 16.6s | 只有评论数；**阅读/点赞/分享/收藏全部 `null`** |

关键发现：

1. **时效**：10:46:02 发布的文章，11:18 已出现在列表里（约 32 分钟内，且未必是上限）。
2. **互动数据拿不到**：H5 通道走未登录页，阅读数只对登录态渲染。要阅读数只能找养登录态的平台。
3. **必须带 User-Agent**：Python 默认 UA 直接 403（Cloudflare）。
4. **URL 里 `chksm` 每次都变**（开发时发现），去重必须归一化到 `__biz+mid+idx+sn`。
5. **正文图片**：HTML 里只有 `data-src` 没有 `src`，且 `&` 被转义为 `&amp;`；`content_text` 不含任何图片，也丢失加粗/颜色。

## 六、为什么选 TikHub 作为第一个上游

- 不用自己养微信账号、不碰风控
- 按量计费、无月费，日常轮询几乎零成本（无新文 1 次调用）
- 文章列表接口近实时、正文接口可用
- 缺点：拿不到阅读数（已确认不需要）；单家依赖 —— 用 raw 存档对冲
